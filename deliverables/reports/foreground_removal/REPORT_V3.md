# 用位姿 + mask 去除前景（家具）—— v3 多视角一致性

日期：2026-09-24 · 工具：`tools/consensus_masks.py`（v3，继 v2 `refuse_with_masks.py`）

## 为什么还有 v3

用户反馈 v2 之后**电视、部分冰箱、壁橱仍未去除干净**。查证发现不是规则写错，
而是**掩膜本身漏检**，且规则无法补偿：

- `masks_keyframes_sam31/by_prompt/remove/` 下，`television`、`refrigerator`、
  `kitchen_cabinet`、`cabinet`、`cupboard`、`furniture` 等**大量提示词的掩膜文件为 0 个**
  （目录存在但为空）；而 `sam31_report.json` 却记着 `television 822450 px`、
  `refrigerator 493127 px`。**报告与磁盘不一致**，逐提示词掩膜没有落盘。
- 最终掩膜覆盖率在关键帧间剧烈抖动：**13.05% ↔ 80.22%**（71 个关键帧）。
- 全像素射线投射定位残留：**74.27% 的残留落在掩膜未覆盖的像素上**，
  只有 25.73% 落在掩膜覆盖处 → **是掩膜漏检为主，不是规则失效**。

## 根因：TSDF 融合对帧取并集

`refuse_with_masks`（v2）逐关键帧把掩膜像素深度置零，这本身没错。但
**TSDF 融合是"任一帧融进去就存在"**：一个物体只有在**所有看到它的关键帧**都被
掩膜覆盖时才会消失。掩膜覆盖率 13%↔80% 抖动，于是只要有一帧漏检，该处家具
就被重新融回来——这正是"电视/冰箱/壁橱还在"的机制。

## 判据：按 3D 点投票，不按 2D 像素

不再逐帧独立决定，而是**按 3D 点**决定：一个点若被"真正看到它的那些视角"中的
**多数**判为前景，就从**所有**视角中剔除。

在基线上按点统计"看到该点的视角中判为前景的比例"，分布明显双峰，投票因此可行：

| 比例 | 占比 |
| --- | --- |
| 0% | 13.41% |
| 0–25%（明确背景） | 14.57% |
| 25–75%（有歧义） | 16.70% |
| >75%（明确前景） | 55.32% |

两个刻意的设计：

- **只统计"看得见"的视角**：看不见该点的视角是**弃权**，而不是投"背景"。
  这才让投票不受覆盖率抖动影响。
- **排除自身视角（leave-one-out）**：点在视角 `i` 的记录上，投票只数 `j != i`。
  于是**自身掩膜漏检的那一帧会被其他视角推翻**，而不是自己给自己背书。
  无其他视角可见时 `seen==0`，调用方回退到该帧自己的掩膜，不会漏处理。

## 数据（射线投射，71 个关键帧）

判据：掩膜覆盖像素处，比较网格命中深度与基线记录的深度（基线融了家具，
所以它记录的**就是**家具表面）。命中≈记录深度 = **家具仍在**。

| 网格 | 家具仍在 | 背景仍吻合（掩膜外） | 内部背景仍吻合 |
| --- | --- | --- | --- |
| 基线（家具已融合） | **97.46%** | 98.30% | 97.87% |
| v2 `refuse_with_masks` | **23.89%** | 97.18% | 97.97% |
| **v3 一致性（本次交付）** | **12.33%** | 87.37% | **95.64%** |

**家具残留 23.89% → 12.33%（约 1.9× 改善）**；相对基线是 7.9×。

### 关于"背景仍吻合"这一列

掩膜外像素里**本身就含有掩膜漏检的家具**（占残留的 74%），所以在那里"不复现"
有一部分是**正确的去除**而非损伤。为避免把正确去除算成损伤，另用更干净的对照：
**距任一掩膜 ≥12px 的内部背景**（几乎不可能是家具）——该列 v3 只从 97.97% 降到
**95.64%**，代价约 2.3 个百分点，而残留近乎减半。这是选择 v3 的依据。

### 投票网格生长的消融

投票在 stride=3 的子采样网格上做，再按最近邻铺回全分辨率；`--consensus-dilate`
可在此之上再膨胀（默认 = stride）：

| 生长 | 家具仍在 | 内部背景仍吻合 |
| --- | --- | --- |
| **默认（=stride）** | **12.33%** | 95.64% |
| 0（纯最近邻） | 17.99% | 96.89% |

**膨胀是真实的取舍而非 bug**：去得更多、也碰到更多背景。默认取"更贴近用户
反馈"的一档（家具残留更低）。

## 与 REPORT_V2 里 11.41% 的对账（重要）

`REPORT_V2.md` 记的 v2 残留是 **11.41%**（"5 个留出关键帧"）。我按该报告自己描述的
判据复算，**复现不出 11.41%**：

| 网格 | 全部 71 帧 | 同样 5 个留出帧（按位置 6/20/34/48/62） |
| --- | --- | --- |
| 基线 | 97.46% | 98.08% |
| v2 | 23.89% | 19.83% |
| v3 | 12.33% | 5.92% |

差异来源可定位：旧脚本 `/tmp/raycast3.py` 用的是**未膨胀的 `masks/`**，而
`REPORT_V2.md` 声称采用 **`masks_inpaint` + 4px 膨胀**。膨胀把轮廓外一圈更模糊的
像素计入分母，那里更可能"仍有残留"，所以按报告所述判据复算会得到更高数值。

**结论**：`REPORT_V2.md` 的 11.41% 与它自己写的配置不一致，**不宜再引用**。
本文所有数字都在**同一套配置（`masks_inpaint` + 4px、射线投射、留出判据）**下重算，
因此 v2↔v3 的对比是自洽的：**23.89% → 12.33%**。

（另注：旧的"5 个留出关键帧" `[6,20,34,48,62]` 实际是**位置下标**，不是
`frame_id`——按 id 取会全部取空。这个歧义也是旧数字难以复现的原因之一。）

## 诚实的局限

1. **残留 12.33% 不是 0**。剩余主要是掩膜系统性漏检（`television`/`refrigerator`
   等提示词根本没落盘掩膜）。**要再降需要修掩膜，而不是再调投票规则**。
2. **背景代价真实存在**：约 2.3 个百分点的内部背景会受影响。
3. **挖掉处留下空洞**：相机从未看到家具背面，那里本就没有几何；补面属于先验/
   扩散的工作，本工具只负责移除，不编造几何。
4. 阈值（stride 3、投票 0.5、掩膜膨胀 4px）在本条走位上标定，换序列需重新标定。

## 与 v2 的关系

v2 `tools/refuse_with_masks.py` 保留（它是 v3 的融合底座，且其坐标约定有单测），
但**不再是推荐路径**：它是逐帧独立的，无法克服掩膜在帧间的漏检。
v3 在其之上补上多视角一致性。两者都只做移除，不做几何编造。
