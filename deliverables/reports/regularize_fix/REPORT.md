# regularize_planes 修复：为什么"部分墙面变平、别的墙面更噪"

生成日期：2026-09-22 · 提交 `4d1b142` · 工具 `tools/regularize_planes.py`

## 一、用户回报与实测确认

> "正则化版本只是把部分墙面变得平整，但同时也在另外的墙面处让噪点更为明显"

**确认成立。** 按渲染器实际口径（方向光下每 5cm 网格内明亮度的标准差，
即肉眼看到的"颗粒感"）逐一量 12 个拟合平面：

| 版本 | 改善 | **恶化** |
| --- | --- | --- |
| 发布版（有缺陷） | 9 | **3**（平面 2 / 6 / 10） |
| 修复版 | 9 | 1 |

法线侧损伤更严重——相对真实表面的偏离：

| 指标 | 发布版 | 修复版 |
| --- | --- | --- |
| 偏离均值 | 10.14° | **1.63°** |
| 偏离 p90 | 39.22° | **5.82°** |
| 偏离 max | 90.00° | **24.84°** |
| **翻转法线**（渲染成暗块） | **1093（0.47%）** | **0** |
| 偏离 >5° 的顶点 | 33.06% | 10.78% |
| 偏离 >30° 的顶点 | 14.18% | **0** |

## 二、三个根因

1. **多平面叠加混合**
   法线混合写在平面循环内，逐面覆写 `out_normals`。实测 **42.7%** 的顶点落在
   某个平面 10cm 带内，其中 **20.7% 同时落在 2 个以上**重叠带内（墙角、墙地交界、
   RANSAC 近重复面）。这些顶点被反复混合，最后处理的平面获胜——结果不匹配任何
   真实表面。这正是"这边被磨平、那边更噪"的直接来源。

2. **定向取自已污染的值**
   `sign(dot(current_normal, plane_normal))` 在近垂直处符号不确定，直接翻转法线，
   渲染成暗块（实测 1093 个，0.47%）。

3. **阴影带大于位移带**
   法线按 10cm 带改写，位置只在 `max_shift`(4cm) 内移动 → **7.2%** 的顶点几何
   完全没动却被改了明暗。且 fade 斜坡让几何相同的邻居拿到不同权重，把法线场从
   "均匀粗糙"推成"一片平 + 一片散"。

## 三、修复

`regularize()` 重构为三个明确阶段：

- **阶段一**：只做位置 snap，每顶点归属**单一**最佳平面（按法线一致性 + 贴近度评分）。
- **阶段二**：**在位移之后**重算几何法线，再跨所有平面累加**一个**加权目标，
  只混合**一次**（取代逐面覆写）。
- **阶段三**：定向取自真实几何法线；结果按 `--max-normal-drift-deg` 封顶，
  超限回落到几何法线——**翻转在结构上不可能发生**。

新增 CLI：`--normal-band`（默认 = `--max-shift`）、`--max-normal-drift-deg`（默认 30）。
运行报告新增 `flipped_normals` / `normal_drift_{mean,p90,max}_deg` / `normal_band`，
使这类损伤可回归——此前只能靠肉眼看视频才能发现。

## 四、稳健性

对 5 组极端参数（宽带 0.20、band > shift 的旧 bug 形状、pull=1.0 配 5° 紧上限、
60° 宽松容差）逐一验证，**全部满足不变量**：零翻转、偏离不超上限。

新增 2 项单测（垂直双墙共享边＝重叠带场景；重叠带只产生一次混合），
全量测试 71 → **73 passed**。

## 六、一处诚实的说明：整帧指标会误导

我最初用**整帧**高频能量做代理指标，结果显示修复版"更噪 +5.01%"，与网格级证据
矛盾。加上未正则化的参照后原因清楚了：

| 渲染 | 整帧代理 |
| --- | --- |
| denoised（无正则化，参照） | 5.1910 |
| regularized（发布版，有缺陷） | 4.4898（−13.51%） |
| fixed（修复版） | 4.7150（−9.17%） |

发布版靠**压制掉真实表面起伏**换来了更低的整帧数值——指标更好是因为它"说谎"。
修复版离未正则化参照更近（0.476 vs 0.701），即在压噪的同时尊重真实几何。

**因此该修复的验收应看逐墙指标或直接看视频，不要用整帧高频能量**——它有奖励
过度平滑的偏向。上表逐墙数据已按此口径给出。
